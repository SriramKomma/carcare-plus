# CarCare+ performance results

Generated by `mvn -q compile exec:java -Dexec.args="benchmark"` on 2026-11-11.

- Java 27.0.1.0.3, Mac OS X aarch64, 8 processors
- **Synthetic data** (made-up words and documents, fixed random seed), not crawled pages
- Each time is the median of 5 runs after 3 warm-up runs (`System.nanoTime`)
- Every row was checked: both methods returned the same answer

## 1. Inverted index build time

Expected O(N) for N words: time per word should stay roughly constant.

| Documents | Words indexed | Build time (ms) | ms per 1,000 words |
|---|---|---|---|
| 100 | 20300 | 8.73 | 0.4303 |
| 500 | 101500 | 39.86 | 0.3928 |
| 1000 | 203000 | 87.46 | 0.4308 |
| 5000 | 1015000 | 533 | 0.5255 |

## 2. Query: inverted index vs linear scan

Linear scan uses already-tokenized documents (the fairest version of the scan). Index lookup is O(1) + O(p); the scan is O(N).

| Documents | Queries | Index (µs per query) | Linear scan (µs per query) | Speed-up |
|---|---|---|---|---|
| 1000 | 200 | 4.89 | 580 | 118.6x |
| 5000 | 200 | 34.59 | 4517 | 130.6x |
